FiribStop UZ 3.0.0 — антифишинговый PWA без файлового антивируса

## Netlify
1. Загрузите все файлы проекта в GitHub-репозиторий, подключённый к Netlify.
2. Дождитесь успешного опубликованного деплоя.
3. Проверьте `https://ВАШ-САЙТ.netlify.app/api/health`: ожидается JSON с `ok: true` и версией `3.0.0`.
4. Проверьте `/api/news`: ожидается JSON с `items`, `sources` и `updatedAt`.
5. Откройте сайт и выполните жёсткую перезагрузку: Ctrl+Shift+R.

Netlify Functions обслуживают `/api/news`, `/api/health`, `/api/radar-data`, `/api/site-security-events` и `/.well-known/assetlinks.json`. RSS-источники иногда бывают недоступны; сайт должен сообщать об этом и не показывать выдуманные публикации.

## Render / Node.js
- Runtime: Node.js 18+
- Build command: `npm install`
- Start command: `npm start`
- Health check: `/api/health`

Для отдельного фронтенда на другом домене установите `CORS_ORIGINS` в список точных разрешённых origin. Заголовкам `X-Forwarded-*` доверяйте только за известным обратным прокси: включите `TRUST_PROXY=1` на таком хостинге. Для same-origin-развёртывания дополнительная настройка CORS не нужна.

## Проверка после обновления
1. Выполните `npm run check`.
2. Проверьте переключение языка и темы, навигацию на телефоне, анализ сообщения и локальную проверку ссылки.
3. Проверьте офлайн-режим и сохранённую ленту новостей.
4. Проверьте OCR скриншота: он должен отказать для файла свыше 10 МБ или изображения свыше 20 мегапикселей.
5. При желании используйте облачную синхронизацию: создайте собственный проект Supabase, выполните `supabase-schema.sql`, укажите URL и только публичный anon/publishable key. Не вставляйте `service_role` или `sb_secret_` ключ в браузер. Синхронизация истории отправляет личные данные в облако только после отдельного согласия.
6. Откройте официальный мониторинг UZCERT и убедитесь, что источник и ограничения данных обозначены ясно.

## Что изменилось в 3.0.0
- Улучшено обнаружение некоторых доменов, которые имитируют бренды с помощью похожих символов; блокируются невидимые и bidi-управляющие символы в адресах.
- Исправлено подключение SDK Supabase, ранее не загружавшегося; добавлена RLS-схема для истории по отдельным аккаунтам.
- Улучшен OCR: ограничены размер и разрешение изображения, ресурсы освобождаются даже при ошибке.
- Уточнена CSP для опциональных внешних библиотек и Service Worker: внешние сайты/API не перехватываются и при ошибках статических файлов не возвращается HTML вместо JS/CSS.
- Антивирус, проверка файлов/APK и карантин не входят в проект.

Локальные проверки — эвристические; отсутствие предупреждений не доказывает безопасность ссылки или сообщения. Проверка ссылок не сверяет адреса с актуальным онлайн-списком вредоносных доменов.
