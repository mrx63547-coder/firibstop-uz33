# FiribStop UZ — Digital Safety 3.0.0

FiribStop UZ — офлайн-first PWA для обучения цифровой безопасности и распознавания мошенничества. В этой версии удалён модуль файлового антивируса и проверки APK; проект сосредоточен на противодействии фишингу и социальной инженерии.

## Возможности

| Модуль | Описание | Офлайн |
|---|---|---|
| Проверка сообщений | Локальный анализ текста: просьбы сообщить код, срочность, угрозы, денежные требования и другие признаки обмана | Да |
| Проверка ссылок | Локальные эвристики для небезопасных схем, доменов с логином/паролем, IP-адресов, приватных сетей, Punycode, сокращателей, доменных зон, портов и возможной имитации брендов | Да |
| Примеры и тренажёр | Учебные сценарии распространённых мошеннических схем | Да |
| Семейный и школьный режимы | Памятки, доверенные контакты, занятия и безопасные сценарии | Да |
| История и резервная копия | Локальное хранение истории и экспорт/импорт пользовательских данных | Да |
| Новости кибербезопасности | RSS-сводки с ссылками на первоисточники | Частично |
| Карты и мониторинг | Справочная визуализация и внешние источники мониторинга | Частично |
| Экстренные контакты | Быстрый доступ к справочным контактам | Да |

**Важно:** анализатор использует эвристики и может ошибаться. Отсутствие предупреждений не доказывает безопасность сообщения или ссылки. FiribStop не является антивирусом, не сканирует файлы/APK и не заменяет системную защиту устройства.

Проверка ссылок не обращается к внешней базе и не определяет репутацию сайта в реальном времени. Баллы — эвристический индикатор, а не вероятность мошенничества.

### Облачная синхронизация (необязательно)

В архиве есть `supabase-schema.sql`. Чтобы включить синхронизацию, создайте собственный проект Supabase, выполните SQL в SQL Editor, а в разделе «Облачная синхронизация» введите URL и **публичный** anon/publishable key. SDK загружается из закреплённой версии CDN только по действию пользователя. Не используйте `service_role` или secret key в браузере. История может содержать личные сообщения; облачная передача запускается только после отдельного согласия и нажатия синхронизации.

## Быстрый старт

Требуется Node.js 18 или новее. Зависимости npm не нужны.

```bash
npm start
```

Откройте `http://localhost:3000`. Для проверки работоспособности откройте `/api/health`.

## Проверка

```bash
npm test
npm run lint:check
# или всё одной командой
npm run check
```

Автоматические тесты проверяют логику и наличие ключевых возможностей, но не заменяют ручное тестирование интерфейса в мобильном и настольном браузерах.

## Развёртывание на Netlify

В репозитории настроены функции `/api/news`, `/api/health`, `/api/radar-data`, `/api/site-security-events` и `/.well-known/assetlinks.json`. Фронтенд и функции разворачиваются на одном домене. После публикации проверьте `/api/health` и `/api/news`. Некоторые внешние источники новостей могут временно быть недоступны; интерфейс показывает это, не создавая вымышленные публикации.

## Развёртывание на Render или другом Node-хостинге

- Runtime: Node.js 18+
- Build command: `npm install`
- Start command: `npm start`
- Health check: `/api/health`

Для отдельного фронтенда используйте `CORS_ORIGINS` со списком точных разрешённых origin. Заголовки прокси доверяются только при `TRUST_PROXY=1` или на Render. Для одного домена дополнительная настройка CORS не нужна. Не публикуйте секреты хостинга в исходном коде.

## Структура проекта

- `index.html` — оболочка PWA
- `styles.css` — интерфейс и адаптивные стили
- `app.js` — интерфейс и локальные сценарии анализа сообщений/ссылок
- `link-checker.js` — изолированный, тестируемый анализ URL
- `server.js` — Node-сервер, RSS-прокси, геоданные и мониторинговые маршруты
- `netlify/functions/` — серверные функции Netlify
- `sw.js` — Service Worker, кэш версии v43
- `manifest.webmanifest` — метаданные устанавливаемого приложения
- `scams.json` — обучающие примеры
- `data/` — локальные геоданные регионов
- `tests/` — автоматические тесты

## Приватность и ограничения

- Локальные проверки сообщения и ссылки выполняются в браузере и сами по себе не отправляют проверяемый текст или адрес на внешний сервис.
- История и настройки хранятся в браузере этого устройства; удаляйте их или экспортируйте только на доверенном устройстве.
- Новости и некоторые функции мониторинга требуют сети. Картографические упоминания в публикациях не равны подтверждённому числу атак.
- Перед публичным запуском выполните `npm test`, проверьте ключевые сценарии в браузере и убедитесь, что в консоли нет ошибок.
